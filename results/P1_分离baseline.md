## 1. 结论先行

**✅ htdemucs 复现成功：实测 cSDR 平均 8.80 dB，官方报 9.00 dB，差 0.20 dB，在预设的 ±0.3 dB 容差内。**

**❌ 我在 M0 写下的一条预期是错的**：当时说 IRM oracle 应在 12~15 dB。
实测只有 **8.95 dB**。12~15 dB 那一档对应的是**多通道维纳滤波（MWF）oracle**，
不是 IRM。已用 5 种 oracle 变体交叉验证过实现无误（见 §3）。

**⚠️ 由此推翻了 M0 定下的一条验收准则**：
"真实模型的成绩必须落在 trivial 和 oracle 之间"。
这句话**只对掩码类方法成立**。Demucs 直接生成波形、能修正相位，
不受掩码天花板约束 —— 实测它在 drums / bass 上已与 IRM oracle 统计上不可区分。

## 3. 为什么 IRM oracle 只有 8.95 dB —— 交叉验证

怀疑实现有 bug，于是在 8 首歌上跑了 5 种 oracle 变体，
用它们**已知的大小关系**来判定（uSDR，均值聚合）：

| oracle 变体 | vocals | drums | bass | other | 平均 |
|---|---|---|---|---|---|
| IRM 幅度掩码（power=1） | 10.52 | 7.83 | 7.01 | 7.15 | 8.13 |
| 真值幅度 + 混音相位 | 11.34 | 8.18 | 6.97 | 6.91 | 8.35 |
| IBM 理想二值掩码 | 11.34 | 8.76 | 7.50 | 7.63 | 8.81 |
| **IRM 功率掩码（power=2）** | 11.78 | 9.04 | 7.99 | 8.12 | **9.23** |
| IRM power=2，n_fft 8192 | 11.84 | 9.00 | 8.31 | 8.26 | 9.35 |

四条都符合已知规律，实现无误：
1. **功率掩码 > 幅度掩码**（power=2 优于 power=1）—— 教科书结论
2. **软掩码 > 硬掩码**（IRM 优于 IBM）
3. **加大 FFT 只带来 +0.12 dB** —— 说明瓶颈不在时频分辨率，而在掩码这个形式本身
4. **"真值幅度 + 混音相位"反而低于 IRM** —— 初看反直觉，实则已知现象：
   把正确幅度配上错误相位，重叠相加后的实际幅度是错的；
   而比值掩码保留了混音局部的幅度-相位一致性

**结论：IRM 在 MUSDB18 上的天花板本来就在 9 dB 附近。是我的预期错了，不是代码错了。**

### vs trivial 下界

| 声部 | Δ | 95% CI | p |

| 平均 | **+14.267 dB** | [+13.594, +15.042] | 0.0000 ✅ |

> **⚠️ 一个必须说清的方法学差异。**
> 主结果表里 htdemucs 的 drums（10.05）看起来**高于** oracle（9.30），

> 诚实的表述是：**htdemucs 在 drums/bass 上已达到掩码天花板附近，

### 5.2 关键发现：**很大一部分"失败"是指标假象，不是算法失败**

统计了每首歌每个声部真值的能量（相对混音，dB），与该声部 SDR 求相关：

| 声部 | Pearson r（真值能量 ↔ SDR） |
|---|---|
| **vocals** | **+0.777** |
| other | +0.553 |
| drums | +0.506 |
| bass | +0.385 |

**人声一项的相关系数高达 0.78。** 机制很直白：SDR 的分母是参考信号能量，
一个声部在混音里本来就很轻时，任何一点串音都会把 SDR 压得极低 ——
这时低 SDR 反映的是"这首歌几乎没有人声"，不是"模型分不出人声"。

典型例子（全体 vocals 相对能量中位数为 -6.8 dB）：

| 曲目 | vocals SDR | vocals 真值能量 | 判读 |
|---|---|---|---|
| PR - Happy Daze | -10.46 dB | **-25.8 dB** | 人声几乎不存在 → **指标假象** |
| PR - Oh No | -0.01 dB | -17.1 dB | 同上 |
| Skelpolu - Resurrection | 1.78 dB | -14.7 dB | 同上 |

### 5.3 真实的算法失败（低 SDR 但真值能量正常）

判据：该声部 SDR 落在最低 25%，**且**真值能量不低于全体中位数。

|---|---|---|---|

| bass | 3.91 dB | -3.3 dB（偏强） | Punkdisco - Oral Hygiene |
| bass | 3.51 dB | -7.2 dB | Hollow Ground - Ill Fate |

| drums | 6.70 dB | -0.6 dB（很强） | PR - Oh No |
| drums | 6.72 dB | -1.6 dB（很强） | Little Chicago's Finest - My Own |

## 6. 对 P2 的规划影响（本报告最有价值的部分）

1. **`other` 轨是最大的改进空间。**
   htdemucs 的 other 只有 6.42 dB，而 IRM oracle 有 8.69 dB —— 差 2.59 dB 且**统计显著**。
   ~~说明纯掩码后处理在 other 上还有实打实的头寸。~~

   > **⚠️ 2026-08-01 更正：删掉的那句话是错的。**
   > 这 2.59 dB 的头寸**只有拿到真值幅度才够得着**。掩码细化用的是模型自己估计的幅度，
   > 它把估计投影到"混音复数谱的实值缩放"这个集合上，而该集合的最优点
   > （IRM oracle 全轨平均 8.95 dB）距离 htdemucs 的 base（8.80 dB）**只有 0.15 dB**。
   > P2 实测软掩码细化在 other 上 **-0.658 dB 且显著变差**，四个声部全部变差。
   > 详见 [P2 消融实验](P2_消融实验.md)。
   >
   > 正确的表述是：**other 轨仍是最大的改进空间，但这个空间只能靠提升幅度/波形估计本身
   > （更强的模型、集成、微调）去拿，掩码后处理拿不到。**

2. **drums / bass 上的掩码类后处理基本没有头寸。**
   两者已与 IRM oracle 不可区分。~~P2-A 计划里的"多通道维纳后处理"
   预期只能在 vocals 和 other 上见效~~ —— **实测是四个声部全部变差**，
   连"没有头寸"都说轻了，是净损失。

3. **P2 的显著性门槛已经量化：曲间标准差 2.25 dB。**
   配对检验在 n=50 下能检出约 ±0.15 dB 的稳定提升（M0 的单测已验证过这个量级），
   所以 0.2 dB 级别的改进是可以被证明的，但必须配对做，不能只报均值。

4. **失败案例的筛选必须先剔除指标假象。**
   P2-D"难例定向优化"如果直接拿 SDR 最低的几首去优化，
   会把大量算力花在"这首歌本来就没人声"这种伪问题上。
   正确做法是用 §5.3 的判据（低 SDR + 正常能量）筛选，已把
   `results/p1_stem_energy.csv` 落盘供后续复用。

5. **报告 SDR 时应同时给出声部能量分布。**
   否则读者无从判断一个低分是模型问题还是数据问题。这一条要写进评测协议。

## 7. 与 M0 预期的逐条对照

| M0 的预期 | 实测 | 判定 |
|---|---|---|
| `silence` uSDR 恰为 0.00 dB | 0.00 dB | ✅ |
| `trivial` cSDR 在 0 dB 上下 | -5.34 dB | ⚠️ 偏低，但方向对（真实音乐比合成数据的 -6.81 高） |
| `oracle` cSDR 在 12~15 dB | **8.95 dB** | ❌ **预期错误**，见 §3 |
| `htdemucs` 复现 ~9.0 dB，误差 ≤ ±0.3 dB | **8.80 dB（差 0.20）** | ✅ |
| 真实模型必须落在 trivial 与 oracle 之间 | drums/bass 已触及 oracle | ❌ **准则本身只适用于掩码方法** |

**两条预期出错，但都是在"设了锚点并如实对照"之后才发现的。**
如果 M1 只跑 htdemucs 一个模型、看到 8.80 就宣布复现成功，
这两个认知错误会一直留到 P2，并让"维纳后处理能涨多少"的预判完全跑偏。
