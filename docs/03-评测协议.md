# 评测协议

> **这是本项目最先要写的代码。** 模型可以换，评测不能松。
> 所有数字必须能用一条命令重新跑出来，且随机种子固定。

---

## 0. 铁律

1. **测试集只在最后跑。** 调参、选模型、搜阈值一律在验证集上做。
2. **每个数字都要写清口径。** SDR 是 cSDR 还是 uSDR？F1 是 macro 还是 micro？阈值是 0.5 还是搜出来的？
3. **必须有 baseline 对照。** 单独一个数字没有信息量。
4. **报均值必须报离散度。** 50 首歌的 SDR，标准差和中位数一起报。
5. **改进要做显著性检验。** 配对 bootstrap 或配对 t 检验，别拿 +0.05 dB 当成果。
6. **失败案例是交付物**，不是可选项。

## 1. 音源分离

### 1.1 数据与切分

| 项 | 值 |
|---|---|
| 数据集 | MUSDB18-HQ |
| 训练 / 测试 | 官方 100 / 50 |
| 验证 | 从训练集里固定切出 14 首（沿用 Demucs 社区惯例），**种子写死** |
| 采样率 | 44100 Hz，**立体声，不许转单声道** |
| Stems | vocals / drums / bass / other |

### 1.2 主指标

**cSDR（museval，官方口径）**
```
对每首歌：按 1 秒切块 → 每块每轨算 SDR → 取该歌该轨所有块的中位数
对全体：50 首歌的该轨中位数值 → 取中位数（museval 惯例）
最终报：4 轨各自 SDR + 4 轨平均
```

**uSDR（辅助）**：整首歌算一个 SDR，50 首取平均。**报出来是为了和 MDX 系工作对齐，不与 cSDR 混用。**

**辅助分解量**：SIR / SAR / ISR，只在做误差分析时看（判断"串音"还是"失真"）。

### 1.3 结果表模板

```
| 模型                    | vocals | drums | bass  | other | 平均  | RTF  | 参数量 | 峰值显存 |
|-------------------------|--------|-------|-------|-------|-------|------|--------|---------|
| mixture-as-stem (平凡)  |        |       |       |       |       |  -   |   -    |    -    |
| IRM oracle (上界)       |        |       |       |       |       |  -   |   -    |    -    |
| htdemucs                |        |       |       |       |       |      |        |         |
| htdemucs_ft             |        |       |       |       |       |      |        |         |
| BS-RoFormer             |        |       |       |       |       |      |        |         |
| ★ ours (A: TTA+ens+WF)  |        |       |       |       |       |      |        |         |
| ★ ours (B: remix-ft)    |        |       |       |       |       |      |        |         |
| ★ ours (C: distilled)   |        |       |       |       |       |      |        |         |
```

> 两行"平凡基线"和"oracle 上界"一定要有：前者证明评测没写错，后者说明还剩多少空间。

### 1.4 消融表模板（P2-A）

```
| 配置                          | vocals | drums | bass  | other | 平均  | Δ平均 | RTF  |
|-------------------------------|--------|-------|-------|-------|-------|-------|------|
| base (单模型, overlap=0.25)   |        |       |       |       |       |   -   |      |
| + overlap 0.5                 |        |       |       |       |       |       |      |
| + TTA(声道交换)               |        |       |       |       |       |       |      |
| + TTA(极性翻转)               |        |       |       |       |       |       |      |
| + Wiener 后处理               |        |       |       |       |       |       |      |
| + Ensemble(htdemucs+RoFormer) |        |       |       |       |       |       |      |
```

**Δ 必须是逐项累加的增量**，这样才能看出哪一步真的有用、哪一步是白花算力。

### 1.5 显著性检验

50 首歌是配对样本（同样的歌，两个方法）。用 **配对 bootstrap**：
```
重采样 50 首（有放回）× 10000 次 → 每次算两个方法的平均 SDR 之差
→ 报 差值的 95% 置信区间；区间不跨 0 才算显著
```

### 1.6 失败案例（必做）

1. 按平均 SDR 给 50 首排序，取最差 5 首 + 最好 3 首
2. 每首记录：**风格标签、SDR、主观听感描述、频谱图截图、失败原因归类**
3. 归类维度参考：`合成人声/人声混响过重`、`失真吉他与人声频段重叠`、`低频不清晰（808 与 kick 混淆）`、`古典弦乐群（无明确 4 轨对应）`、`现场录音/掌声`
4. 输出到 `results/separation_failures.md`，**配可试听的音频片段**

## 2. 音乐分析（P3）

因为不自研，评测目标是**如实测出现成模型在中文/多风格音乐上的表现**。

### 2.1 自建测试集

| 项 | 要求 |
|---|---|
| 规模 | 20~30 首，每首取中间 60 秒 |
| 风格覆盖 | 华语流行 / 国风 / 电子舞曲 / 摇滚金属 / 民谣 / 古典 / 说唱，每类 3~4 首 |
| 标注内容 | BPM、调性、downbeat 时间点、段落边界与标签 |
| 标注方法 | 用 DAW（如 Ableton/Logic）打点导出，比手敲准得多 |
| 标注一致性 | 边界类标注自己隔一周重标一次，报**自我一致率**，说明真值本身的噪声水平 |

### 2.2 指标

| 任务 | 指标 | 容差 |
|---|---|---|
| BPM | Acc1（严格）/ Acc2（允许 2× 或 ½×） | ±4% |
| Beat | F-measure | ±70 ms |
| Downbeat | F-measure | ±70 ms |
| Key | MIREX 加权得分（正确1.0 / 五度0.5 / 相对大小调0.3 / 同主音0.2） | — |
| Chord | WCSR（按时长加权） | 先只评 maj/min 大类，再评带七和弦的细类 |
| 段落边界 | Boundary F-measure | 报 ±0.5s 和 ±3s 两档 |
| 段落标签 | Pairwise F / 段落标签准确率 | — |

> 用 `mir_eval` 库计算，不要自己实现。

### 2.3 交付

`results/analysis_by_genre.md`：**按风格分组的指标表**。
预期结论（要验证）：电子舞曲的 BPM/beat 最好，古典和说唱最差，国风的调性识别会因五声音阶偏弱——**这些如实写出来比藏起来有价值得多**。

## 3. 音乐标签（P4）

### 3.1 数据与切分

- 用 **MTG-Jamendo 官方 split-0** 做主实验（train/val/test）
- 其余 split 用于稳定性检验（有余力时报 5 split 的均值±标准差，非常加分）
- 主实验子集：先 `moodtheme`(18,486/59) 跑通 → `top50tags`(54,380/50) 出正式数字 → 全量 `autotagging`(55,525/183) 为拉伸目标

### 3.2 指标

| 指标 | 口径 | 用途 |
|---|---|---|
| **macro ROC-AUC** | 每标签算 AUC 再平均 | 与文献可比（但会虚高） |
| **macro PR-AUC (= mAP)** | 每标签算 AP 再平均 | ★ **主指标之一**，抗不平衡 |
| **Macro-F1** | 每标签算 F1 再平均 | ★ **主指标之一**，反映长尾 |
| **Micro-F1** | 全局汇总算 F1 | 辅助，看整体 |
| 分类别指标 | genre / instrument / mood 三组分别报上述四项 | ★ **Stem-aware 的证据就在这张表里** |

### 3.3 阈值协议（关键，必须写死）

```
1. 在验证集上，为每个标签独立地在 [0.05, 0.95] 步长 0.01 搜索使该标签 F1 最大的阈值
2. 阈值固定后，一次性应用到测试集
3. 结果表里必须同时报 "阈值=0.5" 和 "阈值=调优" 两行
```
> 预期现象：mAP 两行完全一致（与阈值无关），Macro-F1 显著上升。**这个对比本身就是一个知识点，写进博客。**

### 3.4 阶梯结果表模板

```
| 级别 | 配置                                  | ROC-AUC | mAP  | Macro-F1@0.5 | Macro-F1@tuned | Micro-F1 |
|------|---------------------------------------|---------|------|--------------|----------------|----------|
| L0   | mel + 小CNN (from scratch)            |         |      |              |                |          |
| L1   | 冻结基座 + Linear Probe               |         |      |              |                |          |
| L2   | + Attention Pooling + MLP 头          |         |      |              |                |          |
| L3   | + Asymmetric Loss                     |         |      |              |                |          |
| L4   | + 逐标签阈值优化                      |         |      |              |                |          |
| L5   | ★ + Stem-aware 特征融合               |         |      |              |                |          |
```

### 3.5 Stem-aware 的假设检验（P4 核心）

**假设 H1**：把分离出的 stem 分别提特征后融合，能提升标签性能。
**假设 H2**（更强、更有意思）：**提升主要来自乐器类标签**，风格类次之，情绪类最少。

**验证方式**：
```
| 标签类别       | 标签数 | L4 mAP | L5 mAP | Δ    | L4 MacroF1 | L5 MacroF1 | Δ    |
|----------------|--------|--------|--------|------|------------|------------|------|
| instrument     |   40   |        |        |      |            |            |      |
| genre          |   87   |        |        |      |            |            |      |
| mood/theme     |   56   |        |        |      |            |            |      |
```
**如果 H2 被证伪（instrument 没有涨最多），照样写进报告并分析原因** —— 诚实的负结果比虚假的正结果有价值得多，而且面试时是很好的谈资。

**消融**：只用 vocals stem / 只用 drums / 只用 bass / 只用 other / 全部 —— 看哪个 stem 贡献最大。

### 3.6 错误分析

- 列出 **AP 最低的 20 个标签**，看是"样本太少"还是"标签本身定义模糊"（如 `epic`、`background`）
- 列出 **最常混淆的标签对**（如 `rock` vs `alternative`、`electronic` vs `dance`）
- 输出到 `results/tagging_errors.md`

## 4. 检索（P5）

### 4.1 代理真值定义（必须显式声明局限）

```
库：MTG-Jamendo 测试集（约 1.1 万首）
查询：从库中随机抽 1000 首（查询自身从候选中剔除）
相关性定义：两首歌的标签集合交集 ≥ 3 个标签 → 相关
```

> ⚠️ **在报告里必须写明**：这是基于标签共现的**代理相关性**，不等同于人类听感相似度。共享标签少但听感很像的歌会被判为"不相关"，从而低估性能。

### 4.2 指标

- **Recall@{1, 5, 10, 50}** ← 主指标
- **mAP@10**
- **NDCG@10**（分级相关性：共享标签数越多增益越高）
- **平均标签 Jaccard@10**（辅助，直观）

### 4.3 结果表模板

```
| 表征                              | R@1 | R@5 | R@10 | R@50 | mAP@10 | NDCG@10 | Jaccard@10 |
|-----------------------------------|-----|-----|------|------|--------|---------|------------|
| 随机                              |     |     |      |      |        |         |            |
| 手工特征 (BPM+key+能量)           |     |     |      |      |        |         |            |
| 标签概率向量 (P4 输出)            |     |     |      |      |        |         |            |
| 基座嵌入 零样本                   |     |     |      |      |        |         |            |
| ★ 基座嵌入 + 自训投影头 (InfoNCE) |     |     |      |      |        |         |            |
| ★ 融合 (嵌入 + 标签 + 手工)       |     |     |      |      |        |         |            |
```

### 4.4 索引工程指标

```
| 索引            | 构建时间 | 内存 | QPS | Recall@10 相对 Flat |
|-----------------|----------|------|-----|---------------------|
| IndexFlatIP     |          |      |     | 1.000 (基准)        |
| IndexHNSWFlat   |          |      |     |                     |
| IndexIVFFlat    |          |      |     |                     |
```

### 4.5 人工听感抽查（必做）

随机抽 20 组检索结果自己听，按 `很像 / 有点像 / 不像` 三档打分，报**人工满意率**，并与代理指标对比。**这一条能直接回应"你的代理真值靠谱吗"的质疑。**
