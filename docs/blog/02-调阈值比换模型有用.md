# 多标签分类里，调阈值比换模型有用得多

> 一个不改一行模型代码、不重训、不增加任何参数的改动，
> 带来 **+0.126 Macro-F1**；而我为此折腾的四个模型改动全部无效或有害。

## 先看一个矛盾的现象

我训了六个配置，其中一个用了非对称损失（ASL）—— 一种专门为多标签不平衡设计的
损失函数。看默认阈值（0.5）下的 Macro-F1：

| 配置 | MacroF1@0.5 |
|---|---|
| **ASL** | **0.1738**（最高） |
| BCE + mean 池化 | 0.1211 |

ASL 赢了 0.05，看起来它确实解决了不平衡问题。

但把阈值逐标签调优之后：

| 配置 | MacroF1@0.5 | MacroF1@tuned | 阈值带来的增益 |
|---|---|---|---|
| **ASL** | **0.1738** | **0.2185**（最低） | +0.045 |
| BCE + mean 池化 | 0.1211 | **0.2699**（最高） | **+0.149** |

**ASL 在默认阈值下是所有配置里最好的，调完阈值后却是最差的。**

## 机制

要理解这件事，得先分清两类指标：

- **mAP / ROC-AUC 与阈值无关**。它们衡量的是**排序质量** ——
  模型有没有把正样本排在负样本前面。
- **F1 强依赖阈值**。它衡量的是**在某个切分点上**的精确率与召回率。

MTG-Jamendo top50tags 的标签矩阵密度只有 **6.27%**。也就是说，
模型学会「处处预测接近 0」就能拿到很低的 loss —— 冒烟测试阶段，
`MacroF1@0.5` literally 是 **0.0000**，而 mAP 已经明显高于随机。
**模型学会了排序，只是所有分数都挤在 0.5 以下。**

ASL 做的事情，本质上是**概率平移**：把负样本往下压、正样本往上推，
让更多正样本的预测越过 0.5。

**而逐标签阈值优化把同一件事做得更彻底，而且免费** ——
它不需要改损失、不需要重训、不会以牺牲排序质量（mAP 一字不变）为代价。

→ **在有阈值优化的流水线里，为「让概率过 0.5」而设计的损失函数是多余的，甚至有害。**

ASL 的代价体现在 mAP 上：它比 BCE **一致地差 0.0397（0/5 种子）**，
而且这个结论在两个规模差 3.35 倍的基座上**独立复现**（−0.040 vs −0.041）。
一个结论在两个基座上都成立，才能说它是关于**方法**的，而不是关于某组特征的偶然。

## 阈值优化到底带来多少

在我跑过的每个配置上：

| 配置 | MacroF1@0.5 → @tuned | 增益 |
|---|---|---|
| mel + 小 CNN（从头训） | 0.039 → 0.204 | **+0.165** |
| MERT 线性探针 | 0.081 → 0.275 | **+0.194** |
| MERT + MLP 头 | 0.127 → 0.276 | **+0.149** |
| **当前最佳配置** | **0.171 → 0.297** | **+0.126** |

作为对照，同一批实验里「从线性探针换到 MLP 头」只有 +0.024，
「换 3.35 倍大的基座」只有 +0.012。

**调阈值的收益比换模型大一个量级。**

## 怎么做才是对的

三条纪律，少一条结论就不成立：

**① 阈值只在验证集上搜，然后冻住。**

```python
y_val, p_val = predict(model, val_loader, device)
result.thresholds = tune_thresholds(y_val, p_val, GRID)     # 只用验证集
...
# **用验证集搜出来的阈值**，绝不在测试集上重搜 —— 那是作弊
result.test_scores = evaluate_tagging(y_test, p_test, result.thresholds)
```

在测试集上搜阈值能把数字做得很好看，但那个数字不代表任何东西。

**② 早停看 mAP，不看 F1。**

F1 被固定的 0.5 阈值污染了 —— 用它早停，等于让模型去优化
「概率的绝对位置」而不是「排序质量」，而排序才是阈值优化之后真正剩下的东西。

**③ 逐标签，不是全局一个阈值。**

50 个标签的正例率从 1% 到 30% 不等，共用一个阈值必然对两头都不利。

## 一件容易被忽略的事

阈值优化的收益**随模型变强而变小**：从头训的小 CNN 是 +0.165，
最佳配置是 +0.126。这符合直觉 —— 模型越好，概率标定越接近合理，
需要修正的量越少。

但即使在最佳配置上，它依然是**本项目单项收益最大的改动**。

## 该带走的东西

- **先问「这个指标依赖阈值吗」，再决定要不要改模型。**
  依赖阈值的指标上出现的差距，可能只是标定问题，不是能力问题。
- **一个能被推理期技巧免费拿到的收益，不值得用一个新损失函数去换** ——
  后者要重训、可能损害排序质量，而且很难解释。
- **报 F1 的时候必须说清楚阈值是怎么定的。** 同一个模型，
  阈值从 0.5 换成逐标签调优，Macro-F1 能差 0.15 —— 比绝大多数论文里的模型改进都大。
