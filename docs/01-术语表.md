## A. 音频信号基础

**采样率（Sample Rate, sr）**
每秒采多少个点。CD 标准 44100 Hz（44.1kHz）。**本项目全程锁 44.1kHz 立体声** —— MUSDB18-HQ 就是这个规格，改了 SDR 就没法和论文比。

**声道 / 立体声（Channel / Stereo）**
左右两条独立波形。**不要为了省事转单声道**：分离模型和 SDR 评测都是按立体声定义的。

**比特率（Bitrate）**
MP3 等有损压缩每秒用多少比特。MTG-Jamendo 是 320kbps MP3——已经是有损了，所以在它上面训练的模型天生带一点压缩痕迹的偏差，值得在报告里提一句。

**响度归一化（Loudness Normalization, LUFS）**
不同歌音量差很多，直接喂模型会让"响"变成一个假特征。统一归一化到 -14 LUFS 左右再处理。

**短时傅里叶变换（STFT）**
把波形切成一小段一小段（每段叫一"帧"），每帧做傅里叶变换，得到"时间×频率"的二维复数矩阵。这就是**频谱图（Spectrogram）**。
- **幅度谱（Magnitude）**：每个时频点的能量大小，模型主要看这个
- **相位谱（Phase）**：波形的"对齐信息"，重建音频时需要
- **窗长 / 跳步（n_fft / hop_length）**：切多长、每次挪多远。窗越长频率分辨率越高但时间分辨率越低（**时频不确定性原理**）

**逆变换（iSTFT）**
把频谱变回波形。分离模型输出的是频谱掩码，最后一步靠 iSTFT 出声。

**梅尔频谱（Mel-Spectrogram）**
把频率轴按人耳感知压缩（低频细、高频粗）。维度从上千降到 128 左右，是绝大多数音乐分类模型的标准输入。

**常数 Q 变换（CQT, Constant-Q Transform）**
每个频带对应一个半音，天然对齐音乐的十二平均律。做和弦/调性分析比 mel 更合适。

**色度特征（Chroma）**
把所有八度折叠成 12 个音级（C, C#, D, ... B）。"这一秒里 12 个音各有多少能量"——和弦和调性识别的经典特征。

## B. 音源分离（Source Separation）

**声部 / 音轨（Stem）**
一首歌里的一类声音。本项目标准四轨：`vocals`(人声) / `drums`(鼓) / `bass`(贝斯) / `other`(其他)。

**混音（Mixture / Mix）**
四轨叠在一起的成品，就是我们平时听的歌。分离任务 = 给 mixture，还原 4 个 stem。

**掩码（Mask）**
最主流的分离做法：不直接生成波形，而是预测一个和频谱同形状的 0~1 矩阵，逐点相乘把不属于该 stem 的能量"擦掉"。
- **软掩码（Soft Mask）**：取值连续，效果好
- **理想比值掩码（IRM）**：用真值算出的最优掩码，是**性能上界**，可以拿来当 oracle 参照

**维纳滤波（Wiener Filter）**
一种后处理：已知四轨的粗估计，重新分配每个时频点的能量，强制"四轨之和 = 混音"。通常能白捡 0.2~0.5 dB SDR。**本项目 P2-A 会用**。

**时域 vs 频域模型**
- **时域（Waveform-domain）**：直接输入输出波形，如 Demucs 的卷积部分。没有相位问题
- **频域（Spectrogram-domain）**：处理频谱，如 RoFormer 系。频率结构建模更强
- **混合（Hybrid）**：两条路并行再融合，`htdemucs` 的 "H" 就是 Hybrid

**Demucs / HT-Demucs**
Meta 出的分离模型系列。v4 的 `htdemucs` 是 **Hybrid Transformer Demucs**，MUSDB18 上平均 SDR 约 9.0 dB（微调版 9.20）。**本项目的 baseline**。

**频带切分（Band-Split）**
把频谱按频率切成若干子带，每个子带单独建模再交互。因为低频（贝斯）和高频（镲片）的规律完全不同，分开处理效果更好。

**RoPE（旋转位置编码, Rotary Position Embedding）**
Transformer 里编码"第几帧"的一种方式，靠旋转向量实现，外推性比绝对位置编码好，适合变长音频。

**BS-RoFormer / Mel-Band RoFormer**
Band-Split + RoPE Transformer 的分离模型，当前 MUSDB18 上的 SOTA 梯队，比 htdemucs 高约 1 dB 以上（贝斯轨提升尤其大，从约 8.6 dB 到约 11.3 dB）。**本项目 P1 的强 baseline，P2 的教师模型**。

**SCNet**
另一条频域路线，用稀疏编码器建模子带，MUSDB18-HQ 上约 9.0 dB SDR，胜在算力更省。

## C. 分离的评测指标

**SDR（Signal-to-Distortion Ratio，信号失真比）**
**本项目最重要的数字。** 单位 dB，越高越好。含义：还原出的声音里，"对的成分"比"所有错误成分（残留的其他乐器 + 算法引入的失真）"高多少。

粗略参照：
| SDR | 主观感受 |
|---|---|
| < 4 dB | 明显串音，能听出别的乐器 |
| 6~8 dB | 可用，有轻微水声/金属味 |
| 9~11 dB | 很干净，商用级 |

**⚠️ 两种 SDR，报数必须写清是哪种：**
- **cSDR（chunk-level / museval）**：把歌切成 1 秒的块，每块算一次 SDR，最后取**中位数**。这是 SiSEC/MUSDB 官方口径，论文里报的多是这个
- **uSDR（utterance-level）**：整首歌算一个值，取平均。Music Demixing Challenge 用这个
两者数值差 1~2 dB 很正常，混着比就是耍流氓。

**SIR / SAR / ISR**
SDR 的三个分解量。**SIR**=干扰抑制得多干净（还剩多少别的乐器），**SAR**=算法自身引入的失真有多少，**ISR**=空间/立体声形象保持得如何。SDR 掉了要靠这三个看是"串音"还是"糊了"。

**SI-SDR（尺度不变 SDR）**
消除整体音量缩放影响的变体，语音分离领域常用。本项目报了作参考即可，主指标仍用 museval 的 SDR。

**museval**
MUSDB 官方评测库。**必须用它，不要自己实现 SDR**——自己写的多半和论文不可比。

**Oracle 上界**
用真值算出的理想结果（如 IRM oracle），代表"这个框架下最好能到多少"。报出来能让审稿人/面试官知道你还有多少空间。

## D. 节奏、调性与结构（P3）

**BPM（Beats Per Minute，每分钟拍数）**
速度。80 是慢歌，128 是舞曲，170+ 是 drum & bass。
**倍速歧义（Octave Error）**：算法容易把 70 报成 140 或反过来，这是 BPM 评测的经典坑，评测时通常允许 2 倍/半倍算对（记作 Acc2）。

**拍点（Beat）/ 强拍·小节线（Downbeat）**
Beat = 你跟着点头的那个点。Downbeat = 每小节的第一拍，决定小节线在哪。**混音对齐必须用 downbeat，不能用 beat**，否则两首歌会错开一拍。

**拍号（Time Signature）**
4/4、3/4 之类，一小节几拍。

**调性（Key）**
一首歌的主音和调式，如 C 大调、A 小调。**Mashup 时两首歌调性不合会非常刺耳**，所以 P7 的自动 Mashup 必须先做移调。
- **五度圈（Circle of Fifths）**：判断两个调"和不和"的工具，相邻的调可以直接混
- **相对大小调（Relative Major/Minor）**：C 大调和 A 小调用同一套音，可以互换

**和弦（Chord）**
同时响的一组音，如 Cmaj、Am7、G7。和弦识别输出 `(开始时间, 结束时间, 和弦名)` 序列。

**Krumhansl-Schmuckler 算法**
经典调性识别：统计整曲 12 个音级的能量分布，和 24 个调的"标准模板"求相关，最高的就是答案。Essentia 的 `KeyExtractor` 用的就是这一族方法。

**曲式结构 / 功能段落（Music Structure / Functional Segments）**
intro（前奏）/ verse（主歌）/ chorus（副歌）/ bridge（桥段）/ outro（尾奏）。**副歌定位是混音和"高光片段提取"的关键。**

**all-in-one**
一个模型同时输出 tempo、beats、downbeats、段落边界和段落标签。用**膨胀邻域注意力**建模长时依赖，输入用的是分离后的频谱——和本项目 P1 天然衔接。

**beat_this**
2024 年的拍点跟踪模型，特点是**去掉了传统的 DBN 后处理**、用对标注微小偏移容忍的损失函数，泛化性好（古典、独奏乐器都行）。

**DBN（动态贝叶斯网络）后处理**
传统拍点跟踪的标配：神经网络输出"每帧是拍点的概率"，DBN 再用"节奏应该是规律的"这个先验把它整理成等间隔序列。beat_this 证明了做得好可以不要它。

**评测指标**
- **Beat F-measure**：预测拍点落在真值 ±70ms 内算对，算 F1
- **CMLt / AMLt**：允许整体倍速或相位偏移的宽松指标
- **Chord WCSR（加权和弦符号召回率）**：按时长加权的和弦识别准确率
- **Boundary F-measure**：段落边界在 ±0.5s / ±3s 容差内的 F1
- **Key 加权得分（MIREX）**：完全正确 1.0，五度关系 0.5，相对大小调 0.3，同主音 0.2——因为"错得近"和"错得离谱"不该同分

## E. 音乐标签与分类（P4）

**自动标签（Auto-Tagging）**
给音频打上 rock / happy / guitar 之类的标签。

**多标签分类（Multi-label Classification）**
**注意和多分类的区别**：一首歌可以同时是 rock + energetic + guitar，标签之间不互斥。所以：
- 输出层用 **Sigmoid**，不是 Softmax
- 损失用 **BCE（二元交叉熵）**，每个标签独立算
- 准确率（Accuracy）几乎没有意义（全预测 0 也有 95% 准确率），必须用下面的指标

**ROC-AUC**
受试者工作特征曲线下面积。**在极度不平衡的数据上会虚高**——因为负样本太多，模型随便排一排也很好看。所以音乐标签领域现在更看 PR-AUC。

**PR-AUC / AP / mAP**
- **PR-AUC**：精确率-召回率曲线下面积，对不平衡数据敏感得多，**更能反映真实能力**
- **AP（Average Precision）**：单个标签的 PR-AUC
- **mAP（mean Average Precision）**：所有标签 AP 的平均。**本项目标签任务的主指标之一**

**Macro-F1 vs Micro-F1**
- **Macro**：每个标签单独算 F1，然后**等权平均**。稀有标签和热门标签一样重要 → **对"长尾做得好不好"敏感**
- **Micro**：把所有标签的 TP/FP/FN 汇总起来算一次 F1。被热门标签主导
本项目 **主报 Macro-F1**，因为 183 个标签里大部分是长尾，Macro 才能体现改进。

**阈值优化（Threshold Tuning）**
Sigmoid 输出是 0~1 的概率，要变成 0/1 得定阈值。默认 0.5 对稀有标签是灾难（它的概率可能永远不过 0.3）。**在验证集上给每个标签单独搜最优阈值**，Macro-F1 通常能涨好几个点。
> 关键理解：**mAP 与阈值无关**（它看的是排序），**F1 强依赖阈值**。所以"调阈值后 mAP 不变、MacroF1 大涨"是完全正常的，而且这个对比图很有说服力。

**类别不平衡（Class Imbalance）**及其对策
- **Focal Loss**：降低"已经学会的容易样本"的权重，逼模型关注难样本
- **Asymmetric Loss (ASL)**：专为多标签设计，对正负样本用不同的调制，多标签任务上通常比 Focal 更好
- **类别平衡采样**：让稀有标签的样本被更频繁地抽到

**自监督学习（SSL, Self-Supervised Learning）**
不用人工标注，靠"遮住一部分让模型猜"来学表征。音乐领域的基座模型都是这么来的。

**MERT**
大规模自监督音乐理解模型，用**掩码音频 token 预测**训练（类似 BERT 之于文本）。在多个音乐理解基准上是强 baseline。

**MuQ / Mel-RVQ**
2025 年的自监督音乐表征模型，用 **Mel 残差向量量化（Mel Residual Vector Quantization）** 生成的 token 作为预测目标。
- **RVQ（残差向量量化）**：把连续向量用一串码本索引逼近，第一层量化残差再给第二层量化，层层逼近。是音频离散化的主流做法

**线性探针（Linear Probe）**
冻住基座模型，只在它输出上训一个线性层。**这是衡量"表征本身有多好"的标准做法**，也是本项目 L1 级基线。

**冻结（Frozen） vs 微调（Fine-tune）**
冻结 = 基座参数不动，只训头部，省算力、不容易过拟合。微调 = 基座也一起训，效果上限高但要大量数据和算力。**本项目基座全程冻结**，把算力留给分离。

**注意力池化（Attention Pooling）**
把逐帧特征聚合成一个整曲向量时，让模型自己学"哪些帧重要"，而不是简单平均。对"只在局部出现的乐器"特别关键。

**知识蒸馏（Knowledge Distillation）**
用大模型（教师）的输出当软标签，训练小模型（学生）。**本项目 P2-C 用它做轻量分离模型。**

**消融实验（Ablation Study）**
把改进点一个一个拿掉，看指标掉多少，从而证明"是哪个部分在起作用"。**这是区分"调参碰运气"和"真懂了"的核心证据，本项目每个改进都要配消融表。**

**测试时增强（TTA, Test-Time Augmentation）**
推理时对输入做多种变换（翻转、移位），把多个输出平均。不用重训就能涨点，代价是推理变慢。

## F. 检索（P5）

**嵌入 / 表征（Embedding）**
把一首歌压成一个定长向量（如 768 维），"相似的歌向量也接近"。检索的基础。

**余弦相似度（Cosine Similarity）**
两个向量夹角的余弦，1 表示方向完全一致。音频嵌入检索的默认度量。

**对比学习（Contrastive Learning）**
让"正样本对"（相似的两首歌）的向量靠近、"负样本对"推远。
- **InfoNCE Loss**：一个正样本 vs 一批负样本的分类形式，现在的主流
- **Triplet Loss**：锚点/正样本/负样本三元组，要求"锚-正"距离比"锚-负"小一个 margin

**度量学习（Metric Learning）**
就是学一个"什么叫相似"的距离函数。**本项目 P5 的自研点**：用"共享标签数"当弱监督信号来学。

**弱监督（Weak Supervision）**
没有精确真值，用一个便宜但有噪声的信号代替。本项目用"两首歌共享 ≥3 个标签就算相关"——**是代理真值，必须在报告里注明局限**。

**CLAP / MuLan / MuQ-MuLan**
音频-文本**联合嵌入**模型：把音频和文字描述映射到同一空间，于是可以用"忧郁的钢琴独奏"这句话去搜歌（**零样本文本检索**）。MuQ-MuLan 在文本→音乐检索上优于 LAION-CLAP。**本项目可作为可选的加分功能。**

**零样本（Zero-shot）**
不在目标任务上训练，直接用预训练模型做。

**ANN（近似最近邻搜索）**
精确算全库距离太慢，用近似算法换速度。
- **FAISS**：Meta 的向量检索库，工业标准
- **Flat**：暴力精确检索，作为正确性基准
- **IVF（倒排文件）**：先聚类分桶，只搜最近的几个桶
- **HNSW（分层可导航小世界图）**：图索引，查询极快，内存占用大
**本项目要报"HNSW 相对 Flat 损失了多少召回，换来多少倍加速"——这是工程能力的体现。**

**Recall@K**
真正相关的结果有没有出现在前 K 个里。**本项目检索主指标**（报 K=1/5/10/50）。

**mAP@K / NDCG@K**
- **mAP@K**：不仅看"在不在前 K"，还看"排在多前面"
- **NDCG@K**：带位置折扣的增益，越靠前权重越高，且支持分级相关性（共享 5 个标签比共享 3 个更相关）

**Jaccard 相似度**
两个标签集合的交集/并集。用来度量"检索出来的歌和查询歌的标签有多重合"。

## G. 工程与性能（P6）

**RTF（实时率, Real-Time Factor）**
处理时长 ÷ 音频时长。RTF=0.1 表示处理 1 分钟音频只要 6 秒（快 10 倍）。**RTF < 1 才叫"比实时快"。**

**吞吐 vs 延迟（Throughput vs Latency）**
吞吐 = 每秒能处理多少；延迟 = 单个请求要等多久。异步队列提高吞吐但不降低单次延迟。

**MPS（Metal Performance Shaders）**
Apple Silicon 上 PyTorch 的 GPU 后端。M2 Max 可用，但部分算子不支持会**静默回退到 CPU**，性能测试时要留意。

**帕累托曲线（Pareto Frontier）**
在"效果 vs 成本"平面上画出所有不被支配的点。**本项目 P2-C 用它展示蒸馏成果**：横轴 RTF，纵轴 SDR，画出"这个算力预算下我能做到多好"。

**异步任务队列（Celery / RQ + Redis）**
分离一首歌要几十秒，HTTP 请求不能干等。做法：提交任务立刻返回 job_id，前端轮询进度。

**内容哈希缓存**
以音频文件的哈希为 key 缓存结果，同一首歌不重复计算。

## H. 浏览器音频（P7）

**Web Audio API**
浏览器原生音频框架，用"节点图"组织：源 → 效果器 → 输出。
- **AudioContext**：整个音频图的宿主
- **AudioBufferSourceNode**：播放一段已解码的音频
- **GainNode**：音量（做 Mute/Solo/淡入淡出）
- **StereoPannerNode**：声像左右定位
- **BiquadFilterNode**：双二阶滤波器，做 EQ（低架/高架/峰值）
- **DynamicsCompressorNode**：压缩器，控制动态范围
- **ConvolverNode**：卷积混响，加载脉冲响应（IR）模拟空间
- **AnalyserNode**：取实时频谱做可视化
- **OfflineAudioContext**：离线以远超实时的速度渲染，用来**导出 WAV**

**AudioWorklet**
在**独立的音频线程**里跑自定义 DSP 代码，取代已废弃的 `ScriptProcessorNode`。UI 卡顿不会影响音频，是做实时效果的正确姿势。
> 关键约束：Worklet 线程里**不能分配内存、不能等锁**，否则会爆音（buffer underrun）。

**WASM（WebAssembly）**
在浏览器里跑接近原生速度的编译代码。时间拉伸这种重 DSP 必须用它。

**时间拉伸 / 变调（Time-Stretching / Pitch-Shifting）**
- **变速不变调**：改速度，音高不变（对齐 BPM 用）
- **变调不变速**：改音高，速度不变（对齐调性用）
- **相位声码器（Phase Vocoder）**：频域实现的经典算法，会有"水声"金属感
- **Rubber Band Library**：高质量开源实现，有 WASM 移植和现成的 AudioWorklet 封装。**本项目用它**

**Mashup**
把 A 歌的伴奏和 B 歌的人声拼在一起。要三件事同时成立：**BPM 对齐、调性对齐、downbeat 对齐**。P3 的分析结果就是为这个服务的。

**爆音 / 咔哒声（Click / Pop）**
在非零点突然切换音频会产生。解决办法：所有增益变化都用 `setTargetAtTime` 之类做**几毫秒的平滑过渡**，绝不直接赋值。

## I. 实验方法学（贯穿全项目）

**基线（Baseline）**
用来对比的参照系统。**没有基线的数字没有意义。**

**复现（Reproduce）**
先把别人论文的数字跑出来对上，再谈改进。对不上说明你的评测协议有问题。

**统计显著性**
改进 0.1 dB 可能只是噪声。50 首歌的样本量下，应该报**配对检验或 bootstrap 置信区间**，而不是只报均值。

**过拟合验证集（Overfitting the Val Set）**
反复在验证集上调阈值/选模型，会让验证集数字虚高。**测试集只在最后跑一次。**

**误差分析 / 失败案例（Error Analysis）**
把做得最差的样本挑出来听、看频谱、归类原因。**这是本项目最能体现"你真的听过、真的懂"的部分，也是绝大多数同类项目缺失的一环。**
