# 方案调研与选型

> 调研时间：2026-07-29。开源生态变化快，动手前请复查各仓库最新 README。
> 原则：**能用现成的就用现成的，把自研预算集中在 P2（分离改进）和 P4（标签）两处。**

---

## 1. 音源分离

### 1.1 候选对比

| 方案 | 架构 | MUSDB18(-HQ) SDR | 优点 | 缺点 | 本项目定位 |
|---|---|---|---|---|---|
| **Spleeter** (Deezer) | U-Net 频域 | ~5.9 dB | 极快、依赖少 | 效果已明显落后 | 只作为"历史基线"提一句 |
| **Open-Unmix (UMX)** | BiLSTM 频域 | ~6.3 dB | 代码极干净，适合读懂原理 | 弱 | **教学参照**，用来讲清 mask 机制 |
| **HT-Demucs (demucs v4)** | 混合时频 + Transformer | ~9.0 dB（微调版 9.20） | pip 装完即用，文档全，社区大 | 显存吃得多 | ★ **P1 主 baseline** |
| **BS-RoFormer / Mel-Band RoFormer** | 频带切分 + RoPE Transformer | 比 htdemucs 高约 +1.3 dB；bass 从 ~8.6 → ~11.3 dB | 当前 SOTA 梯队 | 训练成本极高，需社区权重 | ★ **P1 强 baseline + P2 蒸馏教师** |
| **SCNet** | 频域稀疏子带 | ~9.0 dB (MUSDB18-HQ) | 算力/效果比好 | 生态小 | 备选对比项 |

### 1.2 落地路径

- **推理封装**：`demucs` 官方包最省事；RoFormer 系走 [ZFTurbo/Music-Source-Separation-Training](https://github.com/ZFTurbo/Music-Source-Separation-Training)，它把 `mdx23c / htdemucs / bs_roformer / mel_band_roformer / scnet` 统一到一套 `--model_type + --config_path` 接口，**训练、推理、评测都在里面**，是本项目 P2 的主战场。
- **权重来源**：社区权重（如 viperx 的 BS-RoFormer，vocals SDR 约 10.87）；下载后**必须自己在 MUSDB18-HQ 测试集上复测一遍**，不要直接引用别人报的数字。
- **不做的事**：不从零训 RoFormer（8×A100 级别的开销）。

### 1.3 自研切入点（详见 [00-总体大纲](00-总体大纲.md) P2）

优先级排序：**A 推理期增益（零训练）→ B remix 增强微调 → C 蒸馏 → D 难例定向**。
A 路线在 M2 Max 上就能做完并产出完整消融表，是"没有 GPU 也有产出"的保险。

## 2. 音乐分析（节奏 / 结构 / 和弦 / 调性）

| 任务 | 首选 | 备选 | 说明 |
|---|---|---|---|
| 拍点 + 强拍 | [CPJKU/beat_this](https://github.com/CPJKU/beat_this) | madmom `DBNDownBeatTracker` | beat_this 去掉了 DBN 后处理，跨风格泛化好；依赖 PyTorch 2.0+、`rotary-embedding-torch` |
| 曲式结构 | [mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one) | librosa laplacian 分段 | 一个模型出 tempo/beats/downbeats/段落边界+标签；**依赖 NATTEN，Apple Silicon 编译常失败，先验证再依赖它** |
| 调性 | Essentia `KeyExtractor` | librosa chroma + KS 模板（自己写十几行） | 自己写一版能加深理解，也是 fallback |
| 和弦 | madmom CNN+CRF / `autochord` | Chordino (VAMP) | 中文流行的转位和弦、加音和弦识别率会明显偏低，这正好是失败案例素材 |
| 经典特征 | `librosa` | `essentia` | chroma / CQT / onset / RMS，可视化和 baseline 都靠它 |

**一个重要设计决定**：`all-in-one` 的输入本身就是分离后的频谱。所以流程上**先分离、再分析**，两者共享同一份 stem，省一次分离开销。

## 3. 音乐标签（Auto-Tagging）

### 3.1 表征基座对比

| 模型 | 训练方式 | 拿到方式 | 备注 |
|---|---|---|---|
| **MERT** | 掩码音频 token 预测（BERT 式） | HuggingFace | 音乐理解基准上的常青强 baseline，多任务表现稳 |
| **MuQ** | 预测 Mel-RVQ token | HuggingFace / 官方仓库 | 2025 年方法，表征质量强 |
| **MuQ-MuLan** | 音频-文本对比学习 | 同上 | 附带**零样本文本检索**能力，P5 的加分项 |
| **Essentia EffNet-Discogs** | 有监督（Discogs 400 风格） | Essentia 模型库 | **零折腾**、CPU 可跑，是依赖出问题时的保底方案 |
| **CLAP (LAION)** | 音频-文本对比学习 | HuggingFace | 通用音频（不只音乐），检索能力可对比 |

**选型**：主用 MERT 或 MuQ（择一，看下载和依赖是否顺利），Essentia EffNet-Discogs 作保底。全部**冻结**。

### 3.2 数据集

- **MTG-Jamendo**：[官网](https://mtg.github.io/mtg-jamendo-dataset/) / [GitHub](https://github.com/MTG/mtg-jamendo-dataset)
  - 55,525 首（splits 内），183 标签（87 风格 / 40 乐器 / 56 情绪主题）
  - 子集：`top50tags`(54,380/50)、`genre`(55,215/95)、`instrument`(25,135/41)、`moodtheme`(18,486/59)
  - 官方提供 5 组 split，以及**预计算的 mel 频谱 `.npy` 和 Essentia 特征 `.json`**
  - 音频 320kbps MP3；⚠️ **元数据 CC BY-NC-SA 4.0，仅限非商业研究/学术使用；商用需 Jamendo S.A. 书面授权**（README 必须写明）
  - 官方仓库自带 baseline 代码，**用它的 split 和评测口径，数字才可比**

**下载策略**（避免一上来卡在 500GB）：
1. 先下**预计算 mel 特征** → 跑通 L0~L4，出第一版指标
2. 再下 `instrument` 子集（25k 首）的**原始音频** → 做 L5 Stem-aware（这一步必须要音频）
3. 有余力再上全量

### 3.3 自研设计（本项目核心）

见 [00-总体大纲](00-总体大纲.md) P4 的 L0→L5 阶梯。要点重述：
- **注意力池化头**是自己设计的
- **Asymmetric Loss / Focal / 平衡采样** 三选一做对比
- **逐标签阈值优化**——性价比最高的一招
- **Stem-aware Tagging** 是原创假设，要用"按标签类别拆分的收益"来证伪或证实

## 4. 检索

| 组件 | 选型 |
|---|---|
| 嵌入 | MuQ / MuQ-MuLan / CLAP（零样本）+ 自训投影头（微调） |
| 索引 | FAISS：`IndexFlatIP`（基准）→ `IndexHNSWFlat`（生产） |
| 相关性代理真值 | "共享 ≥3 个标签" |
| 指标 | Recall@{1,5,10,50}、mAP@10、NDCG@10、标签 Jaccard |

**参考基准感受**：在 WikiMT-X 这类文本→音乐检索基准上，MuQ-MuLan 的 R@1 约 2.24 / R@10 约 12.11，优于 LAION-CLAP（R@1 0.71 / R@10 6.92）。
→ **说明：跨模态检索的绝对数字本来就很低**，别看到自己 R@1 只有几个点就慌。音频→音频检索的数字会高很多。

## 5. 前端与浏览器 DSP

| 需求 | 选型 | 说明 |
|---|---|---|
| 播放/混音图 | 原生 Web Audio API | 复用已有的 Web Audio Synthesizer 项目结构 |
| 波形显示 | Wavesurfer.js | 多轨、区域标注、缩放都现成 |

## 6. 「不做什么」清单（同样重要）

| 不做 | 理由 |
|---|---|
| 从零训练分离模型 | 算力不允许，且没有增量价值 |
| 训练自己的基座表征模型 | 同上；冻结现成基座 + 自研头部才是正确的资源分配 |
| 文本生成音乐 | 与本项目定位（可验证的理解与分析）冲突 |
| 自研和弦识别 | 边际收益低，用现成的并如实报告其局限 |
| 追求 SOTA 排行榜名次 | 目标是"能说清每个数字怎么来的"，不是刷榜 |
