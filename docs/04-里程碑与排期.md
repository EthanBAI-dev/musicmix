**过程中推翻了自己两条预期**（详见 [DEVLOG](DEVLOG.md)）：
1. **IRM oracle 不是 12~15 dB 而是 8.95 dB** —— 那一档对应 MWF oracle，不是 IRM
2. **"真实模型必须落在 trivial 与 oracle 之间"这条 M0 准则只对掩码方法成立** ——
   Demucs 直接生成波形能修正相位，实测在 drums/bass 上已与 IRM oracle 统计上不可区分

**另外抓到两个方法学陷阱**：
- 中位数聚合与均值聚合会给出**相反**的比较结论（差点错说 htdemucs 超越了 oracle）
- 一大半"失败案例"是**指标假象** —— 声部真值能量与其 SDR 的 Pearson r 高达 0.777（vocals）

## M9（后续计划）：公开部署

> 2026-08-15 记。目标是让别人**打开一个链接就能玩**，而不是 clone 下来配环境。

### 关键约束：前端是静态的，分离不是

| 组件 | 依赖 | 能否静态托管 |
|---|---|---|
| 四轨混音台（播放/EQ/声像/频谱/导出 WAV） | 纯 Web Audio API | ✅ **可以**，一行不用改 |
| 时间轴、失败案例 A/B、分析卡片 | 纯 JS + JSON | ✅ 可以 |
| `POST /api/separate` | Python + PyTorch + **98 MB** htdemucs 权重 | ❌ **不行**，需要后端 |

### 体积清单（实测）

| 组件 | 体积 |
|---|---|
| htdemucs 分离权重 | ~98 MB |
| MERT-v1-95M 基座 | 360 MB |
| MERT-v1-330M 基座 | 1.2 GB |
| **本项目自己训练的标签头** | **~1.7 MB**（420,914 参数） |

自训部分只占 1.7 MB，其余全是冻结基座 —— 这正是 P4/P5 消融的直接后果：
头部怎么改都是噪声，干活的是基座。**部署的重量不在"我做的部分"。**

### 候选方案

1. **GitHub Pages / 同类静态托管**（含 ChatGPT sites 之类）
   - 混音台 + 预分离展示曲，秒开、零冷启动、永远在线
   - **没有分离**。上传按钮需优雅降级（隐藏，而不是点了报错）
2. **Hugging Face Spaces 免费档**
   - 能跑 Python，可直接搬 `scripts/serve.py`
   - 但是 2 vCPU 纯 CPU：本机 M2 Max + MPS 跑 233 秒的歌需 56 秒，
     CPU 上预计慢 5–10 倍 → **一首歌 5–10 分钟**；闲置还会休眠
3. **浏览器内推理（ONNX Runtime Web / WASM）**
   - 用户需下载 98 MB 权重；htdemucs 含复杂 STFT 与 transformer，
     ONNX 导出困难，WASM 速度预计远慢于实时。**不作为第一步**
4. **混合（推荐）**：静态托管混音台，"上传自己的歌"按钮指向 HF Space

### 判断某个托管服务够不够用，只需问一个问题

> **能否跑常驻 Python 进程、装 PyTorch、加载 ~98 MB 权重？**

能 → 整套可搬；不能 → 只能上混音台。

`.gitignore` 已按此配置，部署脚本不要绕过它。
