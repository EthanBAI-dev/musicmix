# 这个项目在做什么（简明版）

> 不用术语的版本。想看数字去 [一页纸总览](../results/SUMMARY.md)。

## 一句话

**上传一首歌，把它拆开、看懂、再重新拼起来。**

## 整条链路

```
一首歌（mp3）
   │
   ├─→ ① 拆轨    人声 / 鼓 / 贝斯 / 其他，四个独立音频
   │
   ├─→ ② 听懂    多少 BPM、什么调、什么和弦、哪段是副歌
   │
   ├─→ ③ 打标签  摇滚？忧郁？有吉他？（50 个标签）
   │
   ├─→ ④ 找相似  库里哪些歌跟它像
   │
   └─→ ⑤ 玩      浏览器里调四轨音量/EQ，或和另一首自动拼成 Mashup
```

## 五个步骤各自怎么做的

### ① 拆轨：用现成的

Meta 开源的 **htdemucs**，直接调用，**没有自己训**。

它就像一个训练有素的调音师，听一遍混音就能把四个声部分开。
我做的是**验证它到底有多准**——在 50 首标准测试曲上跑，
得到 8.80 dB，官方论文说 9.00，差 0.20，在容差内。

> **dB 是什么**：衡量"分出来的人声，有多少是真人声、多少是杂音"。
> 数字越大越干净。8.80 大概是"人声很清楚但仔细听有轻微伴奏残留"。

### ② 听懂：自己写的

- **BPM 和拍点**：用现成的库找节奏，但**"哪一拍是小节的第一拍"是我自己写的**
- **调性**：拿 1982 年一个听觉实验的数据做匹配
- **和弦**：每一拍取一次音高分布，跟 24 个和弦模板比，选最像的
- **曲式**：把相似的段落聚成一类

演示曲上：BPM 猜 95.7（真值 96），调性对，**和弦 8 个全对**。

> 这里有个刻意的克制：段落我只标 `A / B / C`，**不写"副歌"**。
> 算法能判断"这两段像"，但没法知道那叫副歌——
> 编一个更专业的名字会让界面显得聪明，代价是给出假信息。

### ③ 打标签：唯一自己训的模型

用一个叫 **MERT** 的预训练模型把音频变成一串数字（**这部分是冻结的，不训练**），
然后我训一个很小的分类器把这串数字映射到 50 个标签。

**我训的部分只有 1.6 MB，42 万个参数。** 其余 99% 是别人预训练好的。

这不是偷懒，是这个项目最重要的发现（见下面）。

### ④ 找相似：不用向量数据库

全库 5,404 首，每首一个 768 维向量，加起来只有 **15.8 MB**。
检索就是一次矩阵乘法，**9 毫秒**。

我试过加 FAISS 那类近似检索——**反而更慢**，因为矩阵乘法本身就够快了，
近似方法的额外开销比省下的计算还多。所以最后**没有引入这个依赖**。

### ⑤ 玩：纯浏览器

四轨混音台是原生 JavaScript 写的，**零依赖、零构建**。
打开网页就能用：调音量、独奏某一轨、加 EQ、导出 WAV。

自动 Mashup 是把 A 的伴奏和 B 的人声拼起来——
对齐速度、对齐调性、**逐小节对齐节拍**（误差 0.12 毫秒，人耳能分辨的是 20~30 毫秒）。

## 这个项目真正想说明的事

我给标签模型设计了 **7 个改进**，逐个测下来：

| 改动 | 结果 |
|---|---|
| 注意力池化 | ❌ 没用 |
| 最大池化 | ❌ 变差 |
| Focal 损失 | ❌ 变差 |
| ASL 损失 | ❌ 明显变差 |
| 先拆轨再打标签 | ❌ 没用 |
| 换一个大 3.35 倍的模型 | ⚠️ 一开始有用，后来变得多余 |
| **调阈值** | ✅ **有效** |
| **换看歌的哪 30 秒** | ✅ **最有效** |

**六个失败，两个成功——而成功的两个都没有动模型。**

一个改的是"判断标签时用多少分作为分界线"（推理阶段的事），
另一个改的是"喂给模型的是这首歌的哪 30 秒"（输入的事）。

> 歌平均长 201 秒，而我一直只看中间 30 秒——**只看了 15%**。
> 改成看全曲的 4 段（60%），效果提升比换一个大 3.35 倍的模型还多。

## 怎么保证这些结论不是碰运气

每个改动都跑 **5 个不同的随机种子**，看**方向是否一致**。

举例：某次运行里注意力池化"赢"了 0.004——听起来有效。
但 5 次运行之间的波动本身就有 0.009。**赢的那点还没波动大。**

所以判据不是"平均值高了多少"，而是"**5 次里有几次方向一致**"。
5/5 才算成立，3/5 就是噪声。

## 还记录了 7 类"静默失败"

指看起来完全正常、但结果是错的情况。比如：

- 一个算错的音频转换，让分析结果全是 0，**却不报任何错**
- 一个写反的方向，显示的百分比是对的、传下去的值是反的
- 最阴险的一次：**代码算错了，但结论碰巧是对的**

这些都写在开发日志里。发现它们靠的不是"小心"，
而是**每一步都拿能验证的量去核对**——比如"20 秒的歌处理完还应该是 20 秒"。
